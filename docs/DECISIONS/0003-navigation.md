# 0003 — 화면 이동 방식

- 상태: **확정**
- 결정일: 2026-09-04
- 관련 문서: `docs/PRODUCT.md`, `docs/ARCHITECTURE.md`

---

## 배경

화면이 하나뿐일 때는 이동 기능이 필요 없었다.
온보딩(시작 → Companion 선택 → 이름 짓기)이 생기면서 화면 간 이동이 필요해졌다.

앞으로 필요한 화면은 최소한 다음과 같다.

- 온보딩 3화면
- 대화 화면
- Companion 전환 화면
- 설정 / 계정 삭제

---

## 고려한 선택지

| 항목 | A. expo-router | B. React Navigation | C. 라이브러리 없이 상태 전환 |
|---|---|---|---|
| 추가 패키지 | 5 | 4 | 0 |
| 화면 정의 | 파일 구조 = 화면 구조 | 코드로 등록 | 직접 조건 분기 |
| **딥링크** | **기본 제공** | 직접 설정 | 직접 구현 |
| Expo 공식 권장 | ⭕ | — | — |
| 화면 4개 이상일 때 | 무리 없음 | 무리 없음 | **관리 불가** |

---

## 결정

**A. expo-router 를 사용한다.**

---

## 이유

1. **딥링크가 제품 요구사항이다.**
   `docs/PRODUCT.md` 8장의 1.0 기능에 "먼저 연락(알림)"이 포함되어 있다.
   사용자가 알림을 누르면 해당 Companion 과의 대화 화면으로 바로 이동해야 한다.
   expo-router 는 이를 기본으로 처리한다.

2. **전환 비용의 비대칭.**
   C 로 시작하면 화면이 늘어날 때 전부 다시 작성해야 한다.
   지금 도입하는 비용이 가장 작다.

3. **Expo 공식 방식이므로** 문서와 예제가 Expo 버전에 맞춰 유지된다.

---

## 결과로 따라오는 것

- 진입점이 `App.tsx` 에서 `expo-router/entry` 로 바뀌었다.
- `app/` 폴더의 파일 구조가 곧 화면 주소가 된다.
- 딥링크용 `scheme` 을 `app.json` 에 정의했다. (`himher`)
- 네이티브 모듈(`react-native-screens`, `react-native-safe-area-context`)이 추가되어,
  이후 이 패키지들이 바뀔 때는 **앱을 다시 빌드해야 한다.**

### 폴더 규칙

```
app/                    라우트 파일. 얇게 유지한다
├── _layout.tsx         전체 화면 껍데기
├── index.tsx           /
├── companion-select.tsx  /companion-select
└── companion-name.tsx    /companion-name

src/screens/            실제 화면 내용
src/i18n/               사용자에게 보이는 문구
```

**라우트 파일은 화면 컴포넌트를 렌더링만 한다.** 화면 내용은 `src/screens/` 에 둔다.
화면 로직을 라우트 파일에서 분리해야 테스트하기 쉽고, 라우팅 방식이 바뀌어도 화면을 재사용할 수 있다.

---

## 되돌릴 때의 비용

**중간.** 라우트 파일을 걷어내고 화면 전환 코드를 새로 써야 한다.
다만 화면 내용(`src/screens/`)은 그대로 재사용할 수 있으므로,
위 폴더 규칙을 지키는 한 비용은 제한적이다.
